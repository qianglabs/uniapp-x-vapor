# 列表、瀑布流、刷新与滚动

## 选容器前确认滚动行为

| 场景                         | 选择依据                                           |
| ---------------------------- | -------------------------------------------------- |
| 远程分页、很多规则行         | 评估 list-view；来源工程复用 CellList              |
| 不等高双列                   | 来源工程 WaterflowList 封装 Rice Waterflow         |
| 本地少量入口或短列表         | 普通行/scroll-view，避免不必要的原生回收与嵌套手势 |
| 头部与列表整页同步           | 一个主列表及 header，先避免两层各自滚动            |
| 头部先滚、tab 吸顶后内容接续 | 核对目标版本的嵌套滚动能力及现有 ScrollList 实现   |

Rice 源码记录封装原生 waterflow 的 Vapor 问题（issue #29918），因此当前公共组件只走 Rice 实现。这是来源工程的选择；不能推导为所有新版本永远不允许封装原生 waterflow。

当前官方 scroll-view 文档已将旧 `type=nested` 方案标成 Vapor 废弃，并注明部分协商事件仅适用于 Android VDOM。旧复盘中的 `nested-scroll-header/body` 和 `associative-container` 方案必须按目标版本复核，不能作为新 Vapor 页面固定模板。[scroll-view](https://doc.dcloud.net.cn/uni-app-x/component/scroll-view)

## 结构与取数

- `scroll-view` 明确 `direction="horizontal"` 或 `direction="vertical"`，不新增旧 scroll-x/scroll-y。
- 横向直接内容容器明确 `display: flex; flex-direction: row`，并保证真实溢出空间。
- 本工程 `sticky-section` 保守保持一个直接 sticky-header 与一个直接 v-for list-item；骨架、空错态、尾部和 refresher 放在 section 外。它是本项目 bytecode 结构约束，不扩写为跨版本通用定律。
- 作用域插槽由 `itemKey` 查 `Map` 获取业务数据，并处理暂时缺失；不能只用 index 读取当前数组。
- 业务卡片接收可空对象时有安全根节点，不能依靠父 v-if 与 required Prop 同批更新完成收窄。
- 行内子项用业务 ID；多列原生列表的行 key 表达稳定位置和结构，不能拼接所有子 ID 导致头插后整表换 key。不同子树用不同 item type。

## 请求来源与可见状态

| 来源/结果          | 数据                   | 反馈                            |
| ------------------ | ---------------------- | ------------------------------- |
| 尚未加载、首次请求 | 无业务项               | 首帧骨架，不能先闪空态          |
| 切换筛选/数据集    | 依交互清空或保留旧数据 | 显式切换态，旧请求不得覆盖      |
| 下拉刷新           | 通常保留已有项         | refresher，完成/失败/取消均复位 |
| 触底分页           | 追加                   | 只有该请求显示加载尾部          |
| 成功空数据         | 无业务项               | 空态，无多余结束占位            |
| 首次失败           | 无业务项               | 错误与重试                      |
| 追加失败           | 保留已有项和页码       | 可恢复分页，不提前 finished     |
| 确认结束           | 保留已有项             | 按设计展示结束态                |

上传、新建等固定入口不属于“已加载业务数据”，不能用它们抑制骨架。`loading=false` 只代表请求结束，未必代表瀑布流测量完成。

## 骨架与布局完成

双列骨架可作为正常流项参与测量，或用列表外覆盖层；不能塞进整行 `load/load-more` 尾部插槽。列表容器保持常驻。

使用覆盖骨架时，当前项目通过经漏洞证据支持后增加的只读 `layoutcomplete(count)` 事件撤下覆盖层，并匹配当前业务条目数；空结果按请求完成展示空态。事件不是官方通用事件，新项目调用前必须确认组件有这个能力。快速换数时还需核对组件实例/请求代次，单独 count 相等不一定识别旧布局。

骨架与真实卡片统一尺寸、间距和裁切责任。自定义骨架不能再叠公共列表默认内边距；保留动画时明确动画节点与外层裁切节点的圆角。

## 保持容器稳定

包含子项注册、异步测量或尺寸缓存的容器不靠动态 key 重建刷新。筛选时整批换 key 曾触发 Android RenderEffect 主线程空指针，证据包括 minidump、运行库 Build ID 和触发差异；本项目修复在页面提交边界先清旧项、等待 nextTick、复查请求版本再提交新项。

该方案只针对已确认路径。普通刷新、同 ID 更新或需要保留排序位置时，不应默认先清空列表。排序可以保留旧项和折叠缓存，补齐原加载数量后一次替换，避免内容变短截断滚动位置。

## 手势和刷新

- 带 refresher 的隐藏原生列表曾在 v-show 切换后保留手势状态；来源工程对该场景采用互斥挂载，数据/分页留在 composable。不是所有 tab 都必须销毁。
- 短内容没有滚动空间时优先静态行；来源项目“5 条”阈值是局部设计，其他页面应按真实高度决定。
- 程序重载与手势刷新分开，不将所有 reset 都设置 refresher-triggered。
- 程序目标 scrollTop/scrollLeft 与用户实际偏移分开，scroll 通知不无条件回写控制位置，避免拖动回跳。
- 有固定导航时检查占位及视口起点；只改刷新阈值不能修复被导航遮挡。

验收：快速换 tab/筛选、头插、删除、空数据、慢网乱序、连续下拉、刷新中触底、分页失败重试、折叠展开和返回恢复。原生滚动/命中必须真机确认。
