# 弹层、菜单、键盘与输入

## 状态归属与挂载位置

回收列表项只发出打开请求；fixed 弹层、上传来源和选择器声明在页面或功能根组件末尾。隐藏功能组件通过 v-model 受控，所属页面或外层弹层关闭时复位，不只通过 ref 方法修改内部显隐。

复杂切换、返回拦截、多层弹框优先复用当前 Popup/page-container 方案。page-container 支持返回拦截，但它与 dialogPage 覆盖范围不同，不能据此承诺覆盖 pages.json 的原生导航/tabbar。[官方 page-container](https://doc.dcloud.net.cn/uni-app-x/component/page-container.html)

## 一个弹框不是一个布尔值的全部

区分业务 show、原生实例是否挂载、原生 show、打开/关闭阶段、当前请求版本和卸载标记。可用阶段：hidden → opening → opened → closing → hidden。

本项目 App Popup 保持原生容器与插槽常驻，非 App 按需挂载；关闭期间的新打开意图在离场及 closed 引发的业务更新提交后，以最新 show 为准。未提交的打开任务可以取消，旧轮次回调不得重开新状态。

`nextTick` 表示 Vue 更新提交，不证明原生内容已附着、完成测量或绘制。不要把“等待一帧”作为所有空弹层的修复。

## 首开空白、关闭后无法点击

- 重型底部面板含列表、tab、视频时，给原生 page-container 本身明确高度，内部用有约束 Flex 和必要的 min-height: 0；只给插槽内容高度可能首次测量为零。
- 尺寸最终稳定后，若组件确实暴露 relayout，可在 opened 后按当前轮次请求重排，不臆造完成事件。
- 自定义弹层若保留真实节点做离场动画，show=false 同批停止面板/遮罩命中；仅 opacity/transform 不代表不可点击。
- 采集实例、轮次、原生事件和面板边界；诊断日志不应反向控制显隐或自动重试。

修改公共 Popup 前先区分：入口点击没传到、show 不是当前值、运行时 Prop 缺失、测量为零、原生层仍在命中。这些问题的修复位置不同。

## 跟随菜单与多面板

行旁更多菜单可以由功能根部 page-container 承载，通过目标按钮的真实边界和窗口空间定位，空间不足时翻向上方。菜单离场后再交接重命名/删除弹框，保持原交互形态，不直接替换为全屏 ActionSheet。

多个底部面板同时可见时明确各自占位和底部偏移，不只调 z-index。嵌套弹框保持父状态，节点父前子后，并使用有依据的层级。

## 键盘责任独立

通用 Popup 只管显示、关闭、尺寸、原生实例；本项目键盘跟随由 KeyboardPanel 处理，监听实际输入组件的 keyboardheightchange。不在公共 Popup 统一监听全局键盘，不通过内容透明度等待键盘。

先确认是否已有系统 adjust-position，再决定自定义上移，避免两套动画叠加。插槽、输入焦点、面板打开和键盘高度是独立状态，不共用一个隐含开关。

## 数字输入与表单

编辑草稿和已确认值分开。初始化先设置数据并确认节点就绪，再启用用户输入校验；不要由 watch 将后端默认值误当用户输入清空。

输入阶段允许中间文本（例如输入 12 时先有 1），范围/起止顺序按实际需求在 blur/submit 检查。来源工程的时长最终规则为 input 保留草稿与两位小数、blur 做完整范围/顺序回填与提示、submit 再校验；不能从中间历史记录推导为所有字段即时回填。

若需求明确即时显示规范值，必须同时检查业务 ref 与原生 UniInputElement.value。本项目连续同一越界值出现业务 ref 去重而控件显示未恢复，最终在同一 input 事件先同步本次原始值、再写规范值；这是特定控件路径的有证据绕过，使用前复核目标版本，不全局推广。

按钮颜色与提交校验共用规则；无效状态需要具体反馈时，点击直接进入 submit，由 submit 校验。不要用模板短路表达式阻断内部错误提示。

## 提示的宿主

dialogPage 上的确认事件可能早于真实离场，在离场页立刻发 Toast 可能迅速消失。按用户交互选择由业务页持有的稳定提示弹框或在正确离场事件衔接；不加入固定延时猜生命周期。

验收包含：首次/反复打开、关闭中重开、父子交接、返回键、键盘显示/隐藏、取消、卸载、失败重试、列表滑动后入口点击以及关闭后页面继续可点击。
