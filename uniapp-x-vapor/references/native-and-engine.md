# 原生插件、相册、上传与剪辑引擎

## 原生边界

优先目标平台已支持的 uni API；不足时用 UTS 插件，将 Android/iOS/Harmony 原生对象、线程、权限、SDK 和释放封装在平台目录。Vapor 页面只接收具名数据和句柄，不直接操作 Activity、UIView 或 Surface。

标准模式原生组件、native-view 和具体 API 要按目标版本核对，不能因为旧传统 uni-app 插件可用就直接迁入。[UTS 插件](https://doc.dcloud.net.cn/uni-app-x/plugin/uts-plugin.html)、[native-view](https://doc.dcloud.net.cn/uni-app-x/component/native-view.html)

## 桥接错误定位

`UTSCallback cannot be cast to Function1` 类错误先看堆栈所在 API 参数创建路径。本项目 chooseVideo 曾在打开系统选择器前，由当前基座 complete 回调桥接触发类型转换异常；success/fail 已正确包装而 complete 未包装。该调用移除 complete，在已支持分支恢复状态，保留同步异常和卸载保护。

这是特定基座证据，不能把 complete 全局禁用。SDK 初始化成功也不能证明系统媒体 API 桥接、编辑页面或导出成功。

## 相册链路

权限/用途说明 → 读取相册 → 分页资源 → 选择某项 → 导出本地文件/封面 → 上传 → 素材入库。

相册列表保留无扩展名资源，选择后再导出；不能用缩略图路径上传原视频。区分封面、原文件、视频封面和临时缓存，统一在边界转成业务路径协议。

公共路径工具必须约束在授权缓存目录，检查真实目录边界而非相似前缀，错误时清空成功字段并通过现有 error 契约返回。清理仅限自己持有的文件，不能让错误转换扩大删除范围。

iOS 生成 Swift 的循环块/throws 问题见 UTS 参考。Android 通过不能代表 iOS 插件编译通过。

## 上传格式

当前 `utils/uploadFormat.uts` 的有证据策略：原文件名 → 显式 format → 导出路径 → 已识别 MIME → 场景允许的媒体类型默认后缀。tmp/temp 不视为容器，未知 MIME 不参与冲突判断，已识别 MIME 只作兜底。

文件名与显式 format 的冲突仍拦截；场景白名单独立校验，普通素材与混剪可接受格式不同。无格式时视频 mp4、图片 jpg 是本项目用户确认的业务默认，不表示实际内容已转码。

后缀修正与容器转换不同。生成一个 .mp4 文件名不能修复不受支持的编码；需要真实转换时必须调用已接入的能力并验证产物。

## SDK 接入必须核对的闭包

引擎 API、仅预览 Demo、完整编辑 Demo 与商用成品编辑器不同。接入前核对真实页面、跳转、模块、AAR/JAR/SO、资源、清单、权限、授权、混淆和 ABI；不要只以初始化成功验收。

修改原生模块或插件需要按实际要求重打基座。热更新不能替换缺失的原生库；新包是否裁剪 SDK 必须检查包内容，不能只看源码引用。

## 当前剪辑状态与可替换设计

本次快照 `pages/clip/engine/config/index.uts` 静态导出 `providers/none.uts`。剪辑页面保留布局和入口，原生编辑暂未开放；素材选择/预览和智能混剪使用自己的现有链路。

中立契约放 `engine/types.uts`，时间统一毫秒；provider 实现能力判断、不可用说明、初始化、命令执行、预览创建五个导出。页面和通用预览组件不引用厂商类型，适配层处理时间、音量、路径与状态差异。

静态只导出一个 provider，避免先 import 所有厂商再运行时布尔选择。切换到其他引擎不是知识包自动授权事项，需要真实 SDK、目标平台实现和验证；本次没有接入 FFmpeg/阿里等替代品。

## 历史美摄经验

- SurfaceView 尺寸/全屏变化：保持同一 native-view，明确预览尺寸，在真实 surfaceCreated/surfaceChanged 后检查会话和窗口，重连时间线并恢复暂停帧；不要用任意延时。
- Activity 泄漏：原生解绑之外，UTS 句柄也要清空 View 强引用；释放幂等，异常路径同样清理。
- 音乐、转场、原声音量局部修改优先更新现有轨道/属性，避免每次 rebuild 视频时间线造成闪烁。失败保留旧工程或回滚。
- 命令带 revision、会话与取消语义；可选字段显式 null 不等于缺失，过滤时保留 0/false/空字符串。
- 路径归一化覆盖列表所有项，不能只转换旧 music 而遗漏 musicClips。
- 播放时钟与交互草稿分离；用户拖动时不被 SDK 轮询回写，手势结束一次提交，取消丢弃草稿。
- 手柄和缩略帧处于同一滚动坐标系，表达真实片段边界；不要把超出视口的真实边界 clamp 到屏幕制造错误裁切。
- 长按过程中维持触摸目标和滚动方向稳定；单击、拖动、惯性、取消、长按排序分别建模。
- 波形和缩略图避免每帧全量重建；历史实现采用窗口缓存或有上限的峰值聚合，具体数值需依据业务与性能测量。
- UI 插值不增加 SDK seek；SDK 位置为权威采样，暂停/跳转立即定位，连续播放平滑收敛，隐藏取消帧回调。
- 体积报告区分 AAR/运行库、源码缓存、验证 APK 和实际发行包；清缓存不能称为 APK 优化，不能靠删除 ABI 隐藏成本。

这些历史条目原始验证包含模拟、原生编译/打包和仍待真机场景，详见案例档案；本次整理没有重新启用或运行这些能力。
