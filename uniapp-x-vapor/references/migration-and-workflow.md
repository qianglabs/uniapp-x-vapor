# 快速开发、迁移与交付模板

## 从需求到可用链路

1. 定范围：目标平台、入口、参数、视觉基准、交互结果、异常恢复和完成标准。
2. 查事实：项目规范与复盘、当前调用链、官方目标版本能力、API 真实契约。
3. 选复用：搜索组件、composable、API、类型、纯工具和组件库；明确缺口。
4. 画状态：初始化、空/错/加载、刷新/分页、用户动作、隐藏返回、卸载、请求与资源代次。
5. 实现一条闭环：先让入口→数据→UI→操作→反馈→恢复完整工作，再扩展其他分支。
6. 适度拆分：独立外部交互（弹层、选择器）、复杂状态或稳定复用才提取；简单静态区块留在页面。
7. 定点验证：格式、结构、契约、竞态、平台条件，再工具链与真机。检查结果对应实际行为。

## 迁移先写行为映射

```text
入口与参数：来源、必要字段、无效参数反馈
初始化：onLoad/onReady/onShow 的职责和顺序
数据流：route -> API -> response boundary -> state -> UI
用户动作：点击/切换/提交/返回/刷新/分页
状态：首次、成功、空、错误、重试、刷新、追加
依赖：组件、composable、store、缓存、事件、Socket、原生插件
隐藏与卸载：保留什么、暂停什么、清理什么
验收锚点：尺寸/资源/交互位置/请求时机/失败恢复
```

| 旧机制             | 保留               | 替换方向                      |
| ------------------ | ------------------ | ----------------------------- |
| `.vue/.nvue`       | 用户行为、业务状态 | `.uvue` 与目标支持的脚本/组件 |
| Options/mixin/this | 稳定业务规则       | setup/composable              |
| uView Pro          | 外观与交互意图     | 现有 Rice UI/工程组件         |
| z-paging           | 分页、刷新、空错态 | 目标可用的列表能力            |
| renderjs/DOM       | 测量/媒体/动画目的 | Vue 状态、uni 元素 API、UTS   |
| plus.*             | 原生功能结果       | 支持的 uni API 或插件         |
| 旧请求/Socket      | 契约和状态机       | 当前唯一请求层/协议适配       |
| UnoCSS 生成物      | 视觉效果           | 本工程语义 class + 局部样式   |

来源项目的关联工程只读；本知识包没有修改关联工程。新工程对外部参考也应遵循明确授权范围。

## 视觉一致的验收

用户指定参考 UI 时，逐项比较结构层级、区块归属、资源比例、间距、字号、颜色、控件尺寸和操作位置；不能借“Vapor 适配”增加标题、说明、卡片或重排层级。

平台实现允许不同，可感知结果和状态反馈应一致。一个背景替换完成不等于整页视觉还原；一个路由完成不等于发布选择等完整动作链完成。

## 需求提示模板

```text
技术栈：uni-app x / Vue 3 / Vapor / bytecode，脚本沿用当前工程。
平台与工具链：写明 Android/iOS/Harmony/Web/小程序、HBuilderX 与基座。
目标：描述用户完成什么动作，而非只列组件名称。
入口与参数：……
API 契约与实际响应：……
视觉基准：当前 UI / 指定页面或截图。
状态：首次、空、失败、重试、刷新、分页、隐藏返回。
边界：是否需要原生权限/插件；哪些内容只读。
验收：具体场景、允许执行的检查、待设备确认项。
```

## 修复提示模板

```text
复现：平台/系统/工具链/基座，进入路径，操作步骤，期望与实际。
证据：原始堆栈、最小数据、相关日志或截图。
先沿调用链定位，区分页面时序、组件能力、运行产物与原生问题。
不要通过重建容器、固定延时或修改组件库默认绕过。
修正后报告实际检查及仍未确认的根因边界。
```

## 交付说明模板

```text
变化：用户现在可完成的动作与状态反馈。
文件：新增/修改/删除的准确路径和目的。
迁移：保留哪些行为，替换哪些旧技术机制。
证据：实际运行的格式、静态、模拟、编译、打包、设备检查及结果。
限制：未运行的平台、依赖的版本、需要真机重现的场景。
复盘：仅在真实问题已确认并修正时更新，保留不确定边界。
```
